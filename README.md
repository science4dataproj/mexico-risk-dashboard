
- **Ingestion:** Banxico (SIE API) and INEGI (Indicadores API) are fully
  automated — no manual steps, ever. SHCP's public debt data has no
  stable API (see `data/SERIES_METADATA.md`), so it's refreshed manually
  ~once a year via a documented procedure, then parsed by script.
- **Transformation:** all three sources are reconciled into a single
  long-format ("tidy") panel — one row per (date, series, value) — with
  every source-specific date convention documented and handled
  explicitly (see `src/transform/clean.py` docstrings).
- **Analysis:** each series is evaluated against two reference windows
  (full history and a rolling 10-year window), producing descriptive
  statistics, distributional-shape diagnostics, and a fragility
  diagnostic based on rolling autocorrelation and variance trends. See
  "Analysis methodology" below — note this was originally three windows
  (including a structural-break-based "since last regime change"
  window), which was retired after a methodological flaw was found and
  confirmed; see `data/SERIES_METADATA.md`, Decisions Log #11.
- **Reporting:** series-level results are rolled up into 5 economic
  domains, each scored 0–100 on how strongly it shows a *statistically
  significant* trend toward instability — never from the current level
  of a series, deliberately (see "Composite fragility index" below). A
  single composite index and a plain-language scorecard (generated by
  template, not free text) are published as `risk_scorecard.json`.
- **Public dashboard:** a static page (`index.html`) fetches
  `risk_scorecard.json` directly at page-load time. Because the monthly
  pipeline already commits updated data to `main`, **the live dashboard
  reflects new data automatically** — there is no separate deploy or
  rebuild step.
- **CI/CD:** every push and Pull Request runs the automated test suite.
  The monthly refresh workflow fetches new data, re-runs the full
  pipeline, runs tests as a safety gate, opens a Pull Request, and
  auto-merges once checks pass — no manual intervention required for
  routine updates. `main` is branch-protected: all changes, automated
  or manual, go through a Pull Request with passing CI.

## Analysis methodology

Every series is evaluated against **two reference windows**, shown side
by side rather than picking one arbitrarily:

1. **Full history** — maximum statistical power, but may mix distinct
   economic regimes.
2. **Rolling 10 years** — the conventional span of at least one full
   business cycle, avoiding a baseline anchored to only one phase of
   the cycle.

For each (series, window), the pipeline computes:

- **Location/spread:** mean, median, std, min, max, with bootstrap
  confidence intervals.
- **Anomaly detection:** z-score and percentile rank of the latest
  observation; a z-score on the most recent period-over-period change.
- **Distributional shape:** skewness, excess kurtosis, and a
  Jarque-Bera normality test.
- **Fragility trend:** rolling autocorrelation and rolling variance are
  each tested for a significant increasing trend (Kendall's tau). A
  combined flag requires BOTH to be significantly rising — a pattern
  associated in the complex-systems literature (e.g. Scheffer et al.)
  with systems losing resilience before a regime shift.

All p-values across the full batch are corrected together using
Benjamini-Hochberg FDR correction — never per series in isolation.

**A third window — "since the most recent structural break" — was part
of the original v0 design but was retired from production** after a
placebo-style validation showed the underlying Chow test was
misspecified for these series (a straight-line trend fit to 20–35 years
of non-linear macro history makes almost any recent cutoff date look
like a "break," not just genuine regime changes). The full investigation
— including the numbers that exposed the problem — is documented in
`data/SERIES_METADATA.md`, Decisions Log #11, and is kept as an honest
record of a real methodological error found and corrected, not erased
from the project's history.

## Composite fragility index

Individual series are grouped into 5 economic domains (external
stability, liquidity, interest rates, real economy, prices — public
debt is tracked separately and excluded from the index; see
`data/SERIES_METADATA.md` for why) and rolled up into:

- A **domain fragility score** (0–100), built *exclusively* from
  statistically significant trend signals (rising autocorrelation,
  rising variance, or both together) — never from the current level of
  a series. This is deliberate: whether a "high" or "low" level is good
  or bad is often ambiguous and domain-specific (is low unemployment
  good, or a sign of an overheating labor market?), while "is this
  series becoming less stable" is unambiguous regardless of direction.
- A **composite index** — an unweighted average of the 5 domain scores.
- A **plain-language narrative** per domain, generated by template from
  the underlying statistics (never free text), so it's reproducible and
  testable like everything else in the pipeline.

Full methodology, including the exact scoring formula and the score
thresholds, is in `src/reporting/composite_index.py` and
`data/SERIES_METADATA.md`.

## Running it locally

```bash
git clone https://github.com/science4dataproj/mexico-risk-dashboard.git
cd mexico-risk-dashboard
pip install -r requirements.txt

cp .env.example .env
# add your own free Banxico and INEGI API tokens to .env

python -m src.ingestion.banxico
python -m src.ingestion.inegi
python -m src.transform.clean
python -m src.analysis.run_analysis
python -m src.reporting.run_reporting

pytest tests/ -v
```

Open `index.html` locally (via a simple local server, e.g.
`python -m http.server`) to preview the dashboard against your own
generated `data/processed/risk_scorecard.json`.

## Design decisions

Every non-obvious methodological or infrastructure decision made during
this project — including ones that were later reversed, and mistakes
that were found and corrected — is logged in
[`data/SERIES_METADATA.md`](data/SERIES_METADATA.md), so the reasoning
is auditable rather than only living in memory. That log includes, for
example, a real bug where a structural-break test was misattributing a
shock (COVID-19) to a political transition boundary, discovered through
manual sanity-checking rather than any automated alert — worth reading
as a record of how the project's statistical claims were stress-tested,
not just computed.
